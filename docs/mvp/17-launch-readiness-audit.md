# 17 — Launch readiness audit (Android)

**Date:** 29 Aug 2026 · **Version:** 1.0.0+1 · **Verdict: do not ship yet — 4 blockers.**

A release-engineering pass over the Android build, Gradle, Firebase wiring, APK/Play
readiness, security, performance, memory, state management and offline sync, assessed
against one question: *can 50 testers install this on real hardware and use it for a
week without losing data?*

Companion to [`16-architecture-audit.md`](16-architecture-audit.md), which covered the
Dart architecture. This one covers everything between that code and a phone.

## Critical blockers

### C-1 · A lost encryption key permanently bricks the app
`app/lib/core/storage/hive_store.dart:106`

If reading the Hive AES key from `flutter_secure_storage` throws, `open()` catches it
and continues with `cipher = null`, then opens boxes whose frames *are* encrypted.
Hive throws, the throw escapes `AppBootstrap.initialize()`, and the user gets the
"LifeDNA could not start" screen whose only button re-runs the identical path.

`android:allowBackup` is unset (defaults to **true**) and there is no `res/xml` backup
or data-extraction rules file, so Android Auto Backup copies the Hive boxes and the
encrypted preferences to Google Drive — but Keystore keys are device-bound and
non-exportable. **Every device-to-device restore produces encrypted boxes with no
key.** Only recovery is uninstall, which destroys the data.

Second route to the same state: a first launch where secure storage is briefly
unavailable creates *unencrypted* boxes; the next launch opens them *with* a cipher
and fails the other way.

**Fix.** (1) `android:allowBackup="false"` or `dataExtractionRules` excluding Hive and
secure prefs. (2) Persist an `encrypted: true|false` marker outside the encrypted
boxes and refuse to open in the other mode. (3) Replace the dead retry screen with a
reset-and-re-download recovery.

### C-2 · Google Sign-In cannot succeed in any build
`app/lib/core/config/app_bootstrap.dart:64`, `app/lib/features/auth/data/auth_repository.dart:195`

`google_sign_in 6.3.0` on Android sources the OAuth client from the
`default_web_client_id` string resource generated by the `google-services` Gradle
plugin from `google-services.json`. This project ships neither, and the constructor
passes no `serverClientId`. `idToken` will be **null**, and
`GoogleAuthProvider.credential` with a null id token is rejected by Firebase. 100%
failure rate on the first configured build.

Sibling defect: `GoogleCalendarService` passes `clientId`, which the Android
implementation ignores — Android reads `serverClientId`.

**Fix.** Recommended: add per-flavour `google-services.json` and apply
`com.google.gms.google-services`. That file is not a secret (every value is
extractable from any APK) and it also unlocks Crashlytics mapping upload (H-5).
Otherwise pass `serverClientId` (the *web* client ID) by `--dart-define` into both
constructors, and add a test asserting a non-null `idToken`.

### C-3 · A slow upload silently discards the write that followed it
`app/lib/core/sync/outbox.dart:149,152`, `app/lib/core/data/synced_collection.dart:156`

Outbox entries are keyed by `collection/docId` so rapid edits collapse — correct. But
`complete()` deletes that key unconditionally and `_pushOne` hands it a *synthetic*
entry rather than the one it read, so there is nothing to compare.

Sequence: write v1 → push starts on a slow link → user writes v2, overwriting the
queued entry → v1's push returns OK → `complete()` deletes the entry holding **v2**.
Firestore keeps v1 forever; Hive keeps v2, so last-write-wins hides it locally and the
divergence surfaces only on a second device.

`recordFailure()` has the same flaw in reverse: it writes the stale entry's payload
back over the newer one, so a failed push can *revert* a queued write.

Hot path: Live Gym Mode rewrites the session document on **every set**.

**Fix.** Read the stored entry and delete only when `stored.id == pushed.id`
(`OutboxEntry.id` is already a fresh UUID per enqueue). Same guard in
`recordFailure()`. Push the real entry from `_pushOne`. One test per path.

### C-4 · No release binary has ever been produced
Unverified in aggregate: AGP 9.1.0 + Gradle 9.3.1 + Kotlin 2.4.0, core library
desugaring, three flavours, resource shrinking, R8. R8 is the specific risk because
its failures appear only in release builds — see H-2, which is exactly that shape.

**Fix.** Push so the CI matrix compiles all three flavours. That closes the compile
question, not the R8 question: only installing the **release** APK on hardware does.

## High priority

| # | Finding | Where |
|---|---|---|
| **H-1** | `org.gradle.jvmargs=-Xmx8G` exceeds the RAM of a standard CI runner; the daemon is OOM-killed and reports "daemon disappeared unexpectedly". Drop to `-Xmx4G -XX:MaxMetaspaceSize=1G`. | `android/gradle.properties:1` |
| **H-2** | ProGuard lacks `-keepattributes Signature`. `flutter_local_notifications` persists scheduled notifications as Gson JSON and resolves them via `TypeToken`; without the attribute the generic erases and Gson throws in the boot receiver. **Reminders vanish after a reboot, release builds only.** Add `Signature` and `*Annotation*`. | `android/app/proguard-rules.pro` |
| **H-3** | Progress photos are stored at the `ImagePicker` cache path and persisted verbatim. Android reclaims the cache; "Clear cache" wipes it instantly. The record survives with a dangling path and the UI degrades to a placeholder, so the loss is silent. The absolute device path is also written to Firestore. Copy into `getApplicationDocumentsDirectory()/photos/` and store a relative filename. | `body_editor_sheet.dart:209` |
| **H-4** | A 1-second `Timer.periodic` calls unscoped `setState`, rebuilding the whole Live Gym screen; `_ExercisePanel.build` then calls `lastPerformance()`, which walks every completed session and set. ~9 000 objects scanned per second for a user with 300 sessions. Scope the clock; resolve `lastPerformance` on exercise change. | `live_workout_screen.dart:48,394` |
| **H-5** | No `com.google.firebase.crashlytics` Gradle plugin (it requires `google-services`), so no mapping upload — release crashes report as `a.b.c.d(Unknown Source)` during the one phase where crash reports are the point. Resolved with C-2. | `android/app/build.gradle.kts` |
| **H-6** | `launch_background.xml` is hardcoded `@android:color/white` and is used by both the day and night launch themes, while the app defaults to a dark UI. Every cold start is a full-screen white flash. Add `drawable-night/launch_background.xml` or move to the Android 12 SplashScreen API. | `res/drawable/launch_background.xml` |

## Medium priority

| # | Finding |
|---|---|
| **M-1** | Default Flutter launcher icon, and no `mipmap-anydpi-v26` — Android 8+ shrinks it into a white circle. Ship an adaptive icon (foreground / background / monochrome). |
| **M-2** | `cacheSizeBytes: CACHE_SIZE_UNLIMITED` keeps an unbounded second copy of data the UI never reads (Hive is the read path). Bound it to ~40 MB or disable persistence — the outbox already owns offline writes. `firebase_service.dart:47` |
| **M-3** | No `autoDispose` anywhere in `lib/`. Once visited, a stream provider re-reads its whole Hive box on every change to that box for the life of the app. |
| **M-4** | `multiDexEnabled = true` + `androidx.multidex` are dead weight at `minSdk 24` (native multidex since API 21), and the justifying comment is wrong. |
| **M-5** | A regular Hive `Box` keeps all values resident and the decode cache keeps a parsed copy alongside — ~40 MB modelled at five years of heavy logging. Add a ceiling before public release; `LazyBox` if a tester reports an OOM. |
| **M-6** | Last-write-wins is per document and decided by the device clock. Concurrent edits to different fields of one record lose the earlier edit; a skewed clock can lose silently. Acceptable at this scale — document it. |
| **M-7** | The three `com.dexterous.*` receivers are declared both by the plugin and by our manifest. They merge cleanly only while every attribute matches. |
| **M-8** | `firebase_config.dart` points at `docs/mvp/BUILD_CHECKLIST.md`, which does not exist (it is `11-build-checklist.md`), and understates the `google-services.json` requirement — see C-2. |

## Nice to have

- **Deep links from notifications.** Payloads are carried (`supplement:<id>`, `task:<id>`); nothing routes a tap.
- **Data export.** Settings can erase local data but not export it.
- **A versionCode strategy.** All three flavours ship `versionCode 1`; decide the scheme before the second upload.
- **Narrow the ProGuard keeps.** `-keep public class * extends java.lang.Exception` is broader than needed; add `-renamesourcefileattribute SourceFile`.
- **Walk the light theme by eye.** Complete and tested, never reviewed visually.
- **Drain the outbox in parallel.** `SyncEngine.drain()` awaits each entry in turn at a 20 s timeout; a device back from a week offline serialises hundreds of round trips.
