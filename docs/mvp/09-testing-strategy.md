## 4. The test harness

`test/support/test_harness.dart` gives every test an `AppBootstrap` wired to:

- **Hive's memory backend.** `HiveStore.open(inMemory: true)` passes
  `bytes:` to `Hive.openBox`, so no write touches the disk. This matters more
  than it sounds: a `testWidgets` body runs inside a fake async zone where real
  file I/O never completes, so a single disk write left the box lock held and
  the next `clear()` or `close()` hung the entire suite in teardown rather than
  failing. Finding that cost an afternoon; the memory backend removes the class
  of problem.
- **`FakeNotificationService`**, which records what it was asked to schedule.
  Reminder scheduling is the one side effect a unit test cannot otherwise
  observe, and "the app silently stopped reminding me" is exactly the
  regression worth catching. It applies the real service's rules — a past time
  is not scheduled, the master switch gates everything — against the *test's*
  clock, so a suite pinned to a fixed date behaves identically in 2026 and 2030.
- **`FakeConnectivityService`**, which the test drives.
- **`FirebaseStatus.notConfigured`** — local mode, the exact configuration a
  user has on day one.

`test/support/pump.dart` provides `pumpScreen`, `pumpApp`, `pumpSheet`,
`pumpFrames` and `tapVisible`. Two details are load-bearing:

- `pumpScreen` mounts the screen under test **on top of a host page**, because
  an editor that pops itself on save would otherwise pop the last page off the
  router and assert.
- `pumpFrames` pumps a fixed number of frames rather than calling
  `pumpAndSettle`, because a progress ring or a live rest timer never reaches a
  quiet frame — `pumpAndSettle` would time out on exactly the screens most
  worth testing.

## 5. What each layer tests

### Engines — fixture-driven, three implementations
`test/fixtures/engines/` holds golden cases executed by the Dart suite **and**
by the TypeScript suite in `functions/`, and generated by a third independent
implementation in `tool/generate_engine_fixtures.py`. A divergence fails both
builds. That is the mechanism that lets the client preview a number and the
server store the same one.

### Repositories — real Hive, real outbox, fake network
Every repository test drives the actual write path: Hive commit, outbox
enqueue, best-effort Firestore against `FakeFirebaseFirestore`. They assert
the rules that make each feature trustworthy, not the getters:

- a dose logged twice on one day produces **one** record, by construction
- a pull never overwrites a local record that is strictly newer
- personal records are derived, so discarding a session removes its record
- a training-days-only supplement is not marked non-compliant on rest days
- an implausible portion never reaches storage

### Widgets — states first, then interactions
Every screen is asserted to render its empty state without an error, then
driven through its primary interaction. The suite found five layout defects
that no unit test could have: an infinite-height card, two row overflows, four
overflowing dropdowns, an ink-splash assertion, and two stepper buttons whose
icons were never drawn.

### Journeys — headless and on device
Three scenarios: a new user onboarding to a working dashboard; starting and
discarding a workout; and everything surviving a relaunch while offline.

## 6. What is deliberately not tested

| Not tested | Why | Mitigation |
|---|---|---|
| Real Firebase Auth network paths | requires a live project | `firebase_auth_mocks` covers the mapping; the emulator job covers the rest |
| Google Calendar OAuth | requires an interactive consent screen | the repository is tested against a fake service; the boundary is one class |
| Health Connect native reader | not in this build | the Dart layer, state machine and UI are covered; the native side is Sprint 6 |
| R8-shrunk release binary | no Android SDK in this environment | TD-01; a manual install is a Sprint 5 exit criterion |
| Screenshot goldens | brittle across renderer versions | behaviour and layout constraints are asserted instead |

## 7. Running it

```bash
cd app
flutter test                       # 506 tests
flutter test --coverage
dart ../tool/coverage_gate.dart    # per-area report + the 80 % gate
dart ../tool/coverage_gate.dart --report   # the twenty lowest files

cd ../firebase/rules-test
npm ci && npm run emulator         # 39 rules tests

# On a device:
cd ../../app
flutter test integration_test/app_test.dart -d <device>
```
